# DevOps 生命周期完善 — PRD v3.0

> 基于: CALMS 框架 + DevOps 无限循环 + 六可可信基线 + Dokku PaaS
> 目标: 从"能部署"升级到"可观测·可追溯·可审计·可验证·可进化·可自愈"

## 0. 用户画像

| 角色 | 场景 | 痛点 | 与系统触点 |
|------|------|------|------|
| 开发者 | git push 部署 | 无测试门禁，502 才知错 | `git push` → CI → Staging → Prod |
| 运维者 | 故障恢复 | 手动 curl + docker logs | 监控仪表盘 + 自动告警 |
| 安全审计 | 合规检查 | 密码在 Dockerfile 明文 | 密钥管理 + 安全扫描报告 |
| 质量工程 | 上线决策 | 凭感觉而不是数据 | 质量门禁 + M3 验收 |

## 0.5 核心使用场景

### 场景1: 快乐路径 (开发者日常部署) — 六可全覆盖
```
1. git commit → pre-commit 语法检查            [可验证: 阻断错误]
2. git push → CI: php -l + phpunit + Trivy     [可验证: 质量门禁]
3. 门禁通过 → 自动部署 Staging                  [可追溯: 部署事件入 EventStore]
4. Staging 冒烟测试 → 数据对比                  [可审计: 变更记录]
5. 人工确认 → 部署生产                          [可进化: 影子模式验证]
6. 健康检查 → 502 自动重启                      [可自愈: 故障自动恢复]
7. 监控仪表盘 → 告警推送                        [可观察: 全链路可见]
```

### 场景2: 故障恢复 (运维者响应告警)
```
1. Grafana 告警 502 → 手机通知                 [可观察: 实时告警]
2. 查 EventStore → 定位部署版本+变更时间         [可追溯: 事件回溯]
3. 运行回滚脚本 → 验证健康检查                   [可验证: 回滚成功确认]
4. 审计记录: 谁、何时、为何回滚                  [可审计: 不可变日志]
5. 提取错误指纹 → 自动匹配已知修复               [可自愈: 指纹+修复]
6. 更新 Runbook + 错误指纹库                    [可进化: 知识积累]
```

## 1. 问题陈述

**当前状态**: 代码在 Dokku 上跑起来了，但缺失测试、监控、备份、回滚能力
**核心缺口**: git push → 线上是黑盒。不知道部署了什么、有没有测试过、出问题怎么回退
**影响**: 故障发现靠用户报修，恢复靠手动操作，密码在仓库里

## 2. DevOps 无限循环 × 六可融合矩阵

六可理念来自项目架构（`24-trustworthy-baseline.md` + `07-latte-best-practices.md`），在此扩展为 DevOps 全流程可信基线：

```
         可观察 ──────────────────────────────────────┐
         可追溯 ────────────────────────────────────┐ │
         可审计 ──────────────────────────────────┐ │ │
         可验证 ────────────────────────────────┐ │ │ │
         可进化 ──────────────────────────────┐ │ │ │ │
         可自愈 ────────────────────────────┐ │ │ │ │ │
                                            │ │ │ │ │ │
  Plan → Code → Build → Test → Release → Deploy → Operate → Monitor
    │                                                              │
    └──────────────────── Feedback ───────────────────────────────┘
```

### 矩阵详解

| DevOps 阶段 | 可观察 🔭 | 可追溯 📋 | 可审计 📐 | 可验证 ✅ | 可进化 🧬 | 可自愈 🩹 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| **Code** | — | git log | pre-commit 阻断 | php -l 语法 | 编码规范 | lint 自动修复 |
| **Build** | 构建日志 | 构建事件→EventStore | 密钥零明文 | Trivy 扫描 | Docker 层缓存 | 构建失败自动重试 |
| **Test** | 测试报告 | 每次测试结果 | 覆盖率门禁 | phpunit + 变异 | 测试模板库 | 失败用例自动归因 |
| **Release** | 版本号可见 | 发布事件→EventStore | 审批记录 | Staging 冒烟 | 金丝雀发布 | 回滚脚本 |
| **Deploy** | 实时部署状态 | 部署时间线 | 变更审批链 | 健康检查阻断 | 影子模式验证 | 502→自动重启 |
| **Operate** | 资源仪表盘 | 备份时间戳 | 操作审计日志 | 备份可恢复性 | 弹性伸缩 | 故障自动迁移 |
| **Monitor** | Grafana 面板 | 告警时间线 | 告警升级记录 | SLO 达标率 | 阈值自适应 | 告警自动分级 |
| **Feedback** | NPS 仪表盘 | 用户反馈链 | 决策回溯 | A/B 结果 | 经验→Runbook | 错误指纹积累 |

## 4. 六可工程映射 (DevOps 全流程)

### 🔭 可观察 (Observability) — 系统能感知并暴露自身内部状态

| 层面 | 工具 | 数据输出 | 需求 |
|------|------|------|:---:|
| 构建 | Docker build logs | 构建时间 + 层缓存命中率 | — |
| 部署 | `dokku ps:report` | 容器状态 + 端口 + 网络 | R7 |
| 运行时 | 健康检查端点 `/health` | HTTP 200 + DB 连接状态 | R7 |
| 资源 | `docker stats` | CPU/内存/磁盘 | R4 |
| 业务 | Grafana 面板 | QPS + 延迟 P95 + 错误率 | R10 |

### 📋 可追溯 (Traceability) — 任何事件可沿时间线回溯到源头

| 事件类型 | 记录方式 | 追溯粒度 | 需求 |
|------|------|------|:---:|
| 代码变更 | git log + commit hash | 每 commit: 谁+何时+改了什么 | — |
| 构建 | `dokku git:report` | Docker image SHA + 构建时间 | — |
| 部署 | EventStore `deploy` 事件 | 版本号 + 环境 + 操作人 | R8 |
| 配置变更 | EventStore `config` 事件 | 旧值→新值 + 变更原因 | R2 |
| 故障 | EventStore `incident` 事件 | 时间线 + 影响 + 修复 | R12 |
| 备份 | 备份文件名含时间戳 | `backup-{db}-{YYYYMMDD}.sql.gz` | R3 |

### 📐 可审计 (Auditability) — 任何变更可被独立第三方逐项检查

| 审计项 | 阻断机制 | 审计日志 | 需求 |
|------|:---:|------|:---:|
| 代码提交 | pre-commit hook 阻断语法错误 | git reflog | R1 |
| 密钥泄露 | Trivy 扫描阻断 | 扫描报告 | R2, R11 |
| 部署审批 | Staging 冒烟不通过→禁止生产 | 审批记录 | R5 |
| 配置变更 | 密钥不可回读 (`dokku config:get` 需 SSH) | config 变更日志 | R2 |
| 回滚操作 | EventStore `rollback` 带审批 | 谁+何时+为何 | R8 |

### ✅ 可验证 (Verifiability) — 任何断言可通过自动化实验证伪

| 验证项 | 方法 | 失败动作 | 需求 |
|------|------|------|:---:|
| 代码语法 | `php -l` every file | 阻断 commit | R1 |
| 单元测试 | `phpunit --coverage` | 阻断构建 | R6 |
| 安全漏洞 | `trivy image` | 高危阻断部署 | R11 |
| 部署健康 | `curl /health` HTTP 200 | 自动 rollback | R7 |
| 备份恢复 | 每月还原测试 | 告警 | R3 |
| Staging 冒烟 | 关键 API 自动化测试 | 阻断生产部署 | R5 |

### 🧬 可进化 (Evolvability) — 系统能在不破坏现有功能的前提下演化

| 演化机制 | 实现 | 需求 |
|------|------|:---:|
| 新功能影子模式 | Staging 先跑 ≥3 次再上生产 | R5 |
| 知识积累 | 故障→诊断→修复→Runbook→指纹库 | R12 |
| 阈值自适应 | 监控阈值基于历史数据动态调整 | R10 |
| CI/CD 管道 | 新增检查项=新增 Pipeline Step（不改旧 Step） | R9 |
| 错误指纹库 | 每次故障自动提取指纹→下次自动匹配修复 | R12 |

### 🩹 可自愈 (Self-healing) — 系统能自动检测故障并恢复

| 故障类型 | 检测方式 | 自愈动作 | 需求 |
|------|------|------|:---:|
| 进程崩溃 | Dokku checks 失败 | 自动重启容器 | R7 |
| 内存溢出 | `docker stats` 超限 | OOM Kill + 重启 | R4 |
| 502 Bad Gateway | 健康检查失败 | `dokku ps:restart` | R7 |
| 磁盘满 | cron 检测 `/backups` | 自动清理 >7 天备份 | R3 |
| 部署失败 | 新版本健康检查失败 | 自动 `ps:rollback` | R8 |
| 已知错误 | 指纹匹配 | 自动应用已验证修复 | R12 |

## 8. 架构决策

1. **Dokku 作为 PaaS 底座** — `git push` 替代手写 Nginx/端口/SSL 脚本
2. **密钥走 `dokku config:set`** — 不落盘，运行时注入，支持审计
3. **EventStore 作为追溯层** — 所有部署/配置/故障事件不可变记录
4. **健康检查作为自愈触发器** — `/health` 失败 → 自动重启 → 仍失败 → 回滚
5. **错误指纹库作为进化引擎** — 每次故障提取指纹 → 积累修复模式 → 自动匹配
6. **影子模式作为安全网** — 新版本先在 Staging 无流量验证 ≥3 次
