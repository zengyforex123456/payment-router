## 二、逐项分析

### 1. 社区版（免费/开源）🔴 P0

**为什么需要**：商业模式分析明确"开源社区版 → SaaS 入门版 → 专业版源码"三级漏斗。没有社区版，漏斗顶部缺失，获客完全依赖付费广告。

**需要做什么**：
- 将核心路由引擎（`SelectGatewayUseCase` + `DispatchOrderUseCase` + `HandlePaymentWebhookUseCase`）以 Apache 2.0 协议开源
- 限制：社区版仅支持 1A+1B、仅 weighted 策略、无 Dashboard、无告警
- GitHub 公开仓库 + README + 快速开始
- 社区版安装后，管理面板显示"升级到入门版"提示

**新增需求**:
```
R-C1: 社区版限制 — 最大 1A+1B，仅 weighted 策略，无仪表盘
R-C2: GitHub 开源仓库 + Apache 2.0 License
R-C3: 管理面板显示当前版本 + 升级入口
```

### 2. License 授权验证 🔴 P0

**为什么需要**：商业分析指出源码被盗版是最大风险之一。$800 的源码被一个人买了后可以无限转卖。需要域名绑定 + 定期验证。

**需要做什么**：
- 生成 License Key（绑定域名 + 过期时间）
- 专业版/企业版启动时验证 License
- License 服务器端签发，客户端本地缓存验证（避免服务器宕机阻断客户业务）
- 宽限期机制：License 服务器不可达时，缓存有效期内继续运行

**新增需求**:
```
R-L1: License Key 生成 — 绑定域名 + 过期时间 + RSA 签名
R-L2: 离线验证 — 本地缓存 License，服务器不可达时宽限 7 天
R-L3: License 管理面板 — 签发/吊销/续期
```

### 3. 更新订阅管理 🔴 P0

**为什么需要**：商业模式的核心 recurring revenue 来自年费更新（$150/年 × 专业版，$500/年 × 企业版）。没有更新机制 = 没有持续收入。

**需要做什么**：
- 更新包生成（仅含变更文件的 zip）
- 客户管理面板查看更新日志 + 下载更新包
- SaaS 版自动更新（无需客户操作）
- 源码版手动更新（下载 zip → 解压覆盖 → 运行迁移）
- 更新提醒：到期前 30 天/7 天/1 天邮件通知

**新增需求**:
```
R-U1: 更新包生成 — 增量 zip（仅变更文件 + 新迁移 SQL）
R-U2: 更新日志 — 版本号 + 变更列表 + 发布时间
R-U3: 到期提醒 — 到期前 30/7/1 天推送通知
R-U4: 自动续费选项 — Stripe/Paddle 订阅集成
```

### 4. 功能门禁（Feature Flags）🟡 P1

**为什么需要**：同一套代码，不同版本需要开启不同功能。当前 `TenantUsage::hasFeature()` 已定义，但未在 API 层强制校验。

**需要做什么**：
- 中间件层检查当前租户套餐的功能权限
- 社区版：禁止 1A+1B 以上、禁止 dashboard API、禁止告警
- 入门版：禁止 config/export、禁止 DSL 脚本、禁止 OEM
- 专业版：禁止 admin/tenants（多租户）、禁止 OEM
- 企业版：全部开放

**改动**：在 DispatchOrderUseCase 入口加 `checkLimit()` 调用、在路由器层加 feature 中间件。

```
R-F1: 功能门禁中间件 — 根据 tenant tier 拦截越权 API 调用
R-F2: 前端 UI 门禁 — 不可用功能显示"升级以解锁"
```

### 5. 客户门户（用量+升级）🟡 P1

**为什么需要**：客户需要知道"我用了多少、还剩多少、怎么升级"。当前只有 API，没有面向客户的 Web 界面。

**需要做什么**：
- 客户登录后的 Dashboard 首页：用量仪表盘 + 套餐信息 + 升级按钮
- 升级路径清晰可操作：点击"升级到专业版" → 展示定价 → 付款 → 自动升级
- Billing 历史：查看历史账单和发票

```
R-P1: 客户门户 — 用量/套餐/升级/账单
R-P2: 一键升级 — 选择目标套餐 → Stripe 付款 → 自动更新 tier
```

### 6. 免费试用机制 🟡 P1

**为什么需要**：SaaS 获客时，$149/月的定价需要先让客户体验价值。14 天免费试用是 SaaS 行业标准。

**需要做什么**：
- 新注册租户自动获得 14 天入门版试用
- 试用期内全功能开放（包括 Dashboard 和告警）
- 试用到期后自动降级为社区版限制
- 到期提醒：第 7 天/第 13 天邮件通知

```
R-T1: 14 天免费试用 — 新用户自动开通
R-T2: 试用到期自动降级 — 保留数据，功能受限
R-T3: 试用到期提醒 — 第 7/13 天通知
```

### 7. SaaS→源码升级导出 🟡 P1（已有基础）

**为什么需要**：商业模式核心——入门版 SaaS 客户随业务增长升级到专业版源码。当前 `config/export` 已实现，但需完善。

**需要补充**：
- 导出时生成 License Key（绑定客户提供的域名）
- 导出包包含：配置 JSON + 数据库 dump + 安装说明
- 升级指引文档：从 SaaS 到自部署的完整步骤

```
R-M1: SaaS→源码升级包 — License + 配置 + DB dump + 文档
R-M2: 升级后 SaaS 实例自动关闭（避免双跑）
```

### 8. 付款集成 🟡 P2

**为什么需要**：SaaS 订阅和源码买断都需要实际收款能力。

**需要做什么**：
- Stripe Checkout 集成（信用卡 + Apple Pay + Google Pay）
- Paddle 集成（支持 PayPal + 全球税务合规）
- USDT 加密货币支付（服务中国市场卖家）
- Webhook 处理：付款成功 → 自动激活/续期

```
R-B1: Stripe Checkout — 信用卡/Apple Pay/Google Pay
R-B2: Paddle 集成 — 全球税务合规
R-B3: USDT 支付 — TRC20/ERC20
R-B4: 自动激活 — 付款成功 → License 签发 → 邮件发送
```
